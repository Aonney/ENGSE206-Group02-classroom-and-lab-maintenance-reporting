## 2. Acceptance Criteria

### AC-01 — การส่งคำขอแจ้งซ่อมสำเร็จ (FR-CLMRS-01)

- **Given** ผู้ใช้งาน (นักศึกษา/อาจารย์ผู้สอน) เข้าสู่ระบบ CLMRS และอยู่ในหน้า "แจ้งซ่อมอุปกรณ์/ห้องเรียน"
- **When** ผู้ใช้งานกรอกข้อมูลในฟิลด์บังคับครบถ้วนแล้วกดปุ่ม "ส่งฟอร์ม"
- **Then** ระบบบันทึกข้อมูลคำขอลงฐานข้อมูล และแสดงหน้าจอยืนยันพร้อมเลขที่อ้างอิง **Ticket ID** ให้ผู้ใช้เห็นภายใน **3 วินาที**

### AC-02 — ความพร้อมใช้งานของช่องทางมาตรฐาน (FR-CLMRS-01)

- **Given** ระบบเชื่อมต่อเครือข่ายปกติ
- **When** ผู้ใช้งานที่ผ่านการรับรองตัวตนเข้าใช้งานพอร์ทัลแจ้งซ่อม
- **Then** ฟอร์มแจ้งซ่อมมาตรฐานต้องเปิดใช้งานได้ตลอด 24 ชั่วโมง และรองรับทั้งอุปกรณ์มือถือและคอมพิวเตอร์ (Responsive Design)

### AC-03 — การตรวจสอบฟิลด์บังคับ (FR-CLMRS-02)

- **Given** ผู้ใช้งานกำลังกรอกฟอร์มแจ้งซ่อม
- **When** ฟอร์มแสดงผล ฟิลด์ **อาคาร**, **ห้อง**, **หมวดหมู่ปัญหา** และ **รายละเอียดปัญหา** ต้องถูกระบุเป็นฟิลด์บังคับ
- **Then** หากผู้ใช้กดส่งโดยเว้นว่างฟิลด์บังคับใด ๆ ระบบต้องไม่อนุญาตให้ส่งฟอร์ม และแสดงข้อความแจ้งฟิลด์ที่ขาดภายใน **1 วินาที**

### AC-04 — การตรวจสอบไฟล์แนบ (FR-CLMRS-02)

- **Given** ผู้ใช้งานต้องการแนบรูปภาพประกอบปัญหา
- **When** สกุลไฟล์เป็น JPEG/PNG และมีขนาดไม่เกิน 5MB
- **Then** ระบบบันทึกไฟล์แนบเข้ากับรายการแจ้งซ่อมและแสดงตัวอย่าง (Preview) ก่อนการยืนยันส่ง

### AC-05 — การจัดลำดับความสำคัญของงาน (FR-CLMRS-03)

- **Given** มีรายการแจ้งซ่อมที่ต้องประเมินความเร่งด่วน
- **When** เจ้าหน้าที่หรือระบบประเมินรายการตามเกณฑ์ความเร่งด่วนที่ได้รับการยืนยัน
- **Then** ระบบต้องแสดงและจัดลำดับงานตาม Priority ที่กำหนด เพื่อให้งานที่มีความเร่งด่วนได้รับการพิจารณาก่อน

> **หมายเหตุ:** เกณฑ์ Urgent และผู้มีอำนาจกำหนดยังอยู่ภายใต้ **OQ-01**

### AC-06 — การดึงข้อมูลสถานะงานซ่อมบน Dashboard (FR-CLMRS-04)

- **Given** ผู้แจ้งซ่อมเปิดเข้าหน้า Dashboard "รายการแจ้งซ่อมของฉัน"
- **When** หน้าจอเริ่มโหลดข้อมูล
- **Then** ระบบต้องดึงประวัติและสถานะปัจจุบัน เช่น *รับเรื่องแล้ว*, *กำลังดำเนินการ*, *เสร็จสิ้น*, *ปิดงาน* และแสดงผลเสร็จภายใน **2 วินาที**

### AC-07 — การตรวจสอบรายการแจ้งปัญหาซ้ำ (FR-CLMRS-05)

- **Given** มีรายการแจ้งซ่อมหลายรายการที่อาจเกี่ยวข้องกับปัญหาเดียวกัน
- **When** เจ้าหน้าที่เทคนิคเปิดหน้าจัดการรายการแจ้งซ่อม
- **Then** ระบบต้องช่วยแสดงรายการที่อาจซ้ำกันเพื่อให้เจ้าหน้าที่ตรวจสอบและดำเนินการตามวิธีจัดการรายการซ้ำที่ได้รับการยืนยัน

> **หมายเหตุ:** วิธี **รวม / เชื่อม / ปิดรายการ** ยังอยู่ภายใต้ **OQ-03**

### AC-08 — กระบวนการปิดงานและการยืนยัน (FR-CLMRS-06)

- **Given** เจ้าหน้าที่เทคนิคดำเนินการแก้ไขปัญหาเรียบร้อยแล้ว
- **When** เจ้าหน้าที่บันทึกผลการทำงานและส่งคำขอปิดงาน
- **Then** ระบบต้องดำเนินการเปลี่ยนสถานะเป็น "ปิดงาน" ตาม Workflow และ Role ของผู้มีหน้าที่อนุมัติที่ได้รับการยืนยัน

> **หมายเหตุ:** ผู้ยืนยันการปิดงานยังอยู่ภายใต้ **OQ-02**

### AC-09 — การติดตามการส่งต่องานระหว่างหน่วยงาน (FR-CLMRS-07)

- **Given** รายการแจ้งซ่อมจำเป็นต้องส่งต่อไปยังหน่วยงานอื่น
- **When** เจ้าหน้าที่ทำการส่งต่องาน
- **Then** หน้าจอรายละเอียดงานต้องแสดงผู้รับผิดชอบปัจจุบันและประวัติการส่งต่องานทั้งหมดใน Timeline เดียวกัน

> **หมายเหตุ:** Workflow การส่งต่อและผู้รับผิดชอบแต่ละขั้นยังอยู่ภายใต้ **OQ-06**

### AC-10 — การแจ้งเตือนเมื่อสถานะเปลี่ยนแปลง (FR-CLMRS-08)

- **Given** สถานะของรายการแจ้งซ่อมมีการเปลี่ยนแปลง
- **When** ระบบบันทึกการเปลี่ยนสถานะ
- **Then** ระบบแจ้งเตือนไปยังผู้แจ้งซ่อมตามช่องทางและเงื่อนไขที่ได้รับการยืนยัน

> **หมายเหตุ:** ช่องทางการแจ้งเตือนยังอยู่ภายใต้ **OQ-04**

### AC-11 — การออกรายงานสถิติสำหรับผู้ดูแลอาคาร/ผู้บริหาร (FR-CLMRS-09)

- **Given** ผู้ดูแลอาคารหรือผู้บริหารเลือกช่วงเวลาและขอบเขตข้อมูลที่ต้องการดู
- **When** กดปุ่ม "สร้างรายงาน"
- **Then** ระบบประมวลผลและแสดงรายงานสรุป เช่น จำนวนงานทั้งหมด สัดส่วนสถานะงาน และประเภทปัญหาที่พบบ่อย

> **หมายเหตุ:** รายการ KPI หรือรูปแบบรายงานที่ต้องการเพิ่มเติมยังอยู่ภายใต้ **OQ-05**

### AC-12 — การควบคุมสิทธิ์ตามบทบาทผู้ใช้ (NFR-CLMRS-01)

- **Given** ผู้ใช้งานเข้าสู่ระบบด้วย Role ที่มีสิทธิ์จำกัด
- **When** พยายามเข้าถึงหน้าหรือฟังก์ชันที่ไม่มีสิทธิ์
- **Then** ระบบต้องปฏิเสธการเข้าถึงและแสดง `403 Forbidden` ภายใน **1 วินาที**

## 4. Use Case Specification

### UC-01 — แจ้งปัญหาอุปกรณ์ / ห้องเรียน

| Field | Detail |
|---|---|
| Primary Actor | นักศึกษา, อาจารย์ผู้สอน |
| Trigger | พบอุปกรณ์หรือห้องเรียน/ห้องปฏิบัติการชำรุด |
| Preconditions | ผู้ใช้งานสามารถเข้าสู่ระบบได้ |
| Main Success Scenario | 1. ผู้ใช้งานเข้าสู่ระบบ 2. เลือกเมนูแจ้งปัญหา 3. กรอกข้อมูลที่จำเป็น 4. กดส่งรายการ 5. ระบบตรวจสอบข้อมูล 6. ระบบบันทึกรายการ 7. ระบบสร้าง Ticket ID 8. ระบบแสดงเลขที่อ้างอิง |
| Alternate / Exception Flows | A1. ข้อมูลไม่ครบ → ระบบแจ้งฟิลด์ที่ขาดและไม่บันทึกข้อมูล |
| Postconditions | รายการแจ้งซ่อมถูกบันทึกพร้อม Ticket ID |
| Related Requirements | FR-CLMRS-01, FR-CLMRS-02 |

### UC-02 — ติดตามสถานะงานซ่อม

| Field | Detail |
|---|---|
| Primary Actor | นักศึกษา, อาจารย์ผู้สอน |
| Trigger | ต้องการทราบความคืบหน้าของงาน |
| Preconditions | มีรายการแจ้งซ่อมที่ผู้ใช้งานเป็นผู้แจ้งหรือมีสิทธิ์ดู |
| Main Success Scenario | 1. เปิด Dashboard 2. เลือกรายการแจ้งซ่อม 3. ระบบตรวจสอบสิทธิ์ 4. ระบบแสดงสถานะปัจจุบัน 5. ผู้ใช้งานดูรายละเอียด |
| Alternate / Exception Flows | A1. ไม่พบรายการ → ระบบแสดงข้อความไม่พบข้อมูล |
| Postconditions | ผู้ใช้งานทราบสถานะงานล่าสุด |
| Related Requirements | FR-CLMRS-04 |

### UC-03 — จัดลำดับงานซ่อม

| Field | Detail |
|---|---|
| Primary Actor | เจ้าหน้าที่เทคนิค |
| Trigger | มีรายการแจ้งซ่อมที่ต้องประเมินความเร่งด่วน |
| Preconditions | มีรายการแจ้งซ่อมและข้อมูลเพียงพอสำหรับการประเมิน |
| Main Success Scenario | 1. เจ้าหน้าที่เปิดรายการงาน 2. ตรวจสอบรายละเอียด 3. ประเมินความเร่งด่วนตามเกณฑ์ที่ยืนยัน 4. ระบบกำหนด Priority 5. เจ้าหน้าที่ตรวจสอบคิวงาน |
| Alternate / Exception Flows | A1. เกณฑ์ Urgent ยังไม่ยืนยัน → ใช้ OQ-01 เป็นประเด็นที่ต้องตัดสินใจก่อนกำหนดกฎถาวร |
| Postconditions | งานมีข้อมูล Priority สำหรับใช้จัดลำดับ |
| Related Requirements | FR-CLMRS-03 |

### UC-04 — ตรวจสอบรายการแจ้งซ้ำ

| Field | Detail |
|---|---|
| Primary Actor | เจ้าหน้าที่เทคนิค |
| Trigger | พบรายการที่อาจเป็นปัญหาเดียวกัน |
| Preconditions | มีรายการแจ้งซ่อมในระบบ |
| Main Success Scenario | 1. เปิดรายการ 2. ตรวจสอบอาคาร ห้อง และรายละเอียดปัญหา 3. เปรียบเทียบรายการที่เกี่ยวข้อง 4. ระบุรายการที่อาจซ้ำ 5. ดำเนินการตามวิธีจัดการที่ได้รับการยืนยัน |
| Alternate / Exception Flows | A1. ไม่ใช่รายการซ้ำ → ดำเนินการตาม Workflow ปกติ |
| Postconditions | รายการที่ซ้ำหรือเกี่ยวข้องกันถูกระบุเพื่อดำเนินการต่อ |
| Related Requirements | FR-CLMRS-05 |

### UC-05 — บันทึกผลและปิดงานซ่อม

| Field | Detail |
|---|---|
| Primary Actor | เจ้าหน้าที่เทคนิค, ผู้รับผิดชอบ / ผู้ยืนยันการปิดงาน |
| Trigger | งานซ่อมดำเนินการเสร็จ |
| Preconditions | งานอยู่ในสถานะที่สามารถส่งขอปิดงานได้ |
| Main Success Scenario | 1. เจ้าหน้าที่เปิดรายการ 2. บันทึกผลการซ่อม 3. ระบุข้อมูลการดำเนินงาน 4. ส่งคำขอปิดงาน 5. ผู้มีหน้าที่รับผิดชอบตรวจสอบ 6. ยืนยันตาม Workflow 7. ระบบเปลี่ยนสถานะเป็น "ปิดงาน" |
| Alternate / Exception Flows | A1. ผลการซ่อมไม่ครบ → ไม่อนุญาตให้ดำเนินการปิดงาน A2. ไม่ได้รับการยืนยัน → ส่งกลับเพื่อดำเนินการเพิ่มเติม |
| Postconditions | งานมีผลการซ่อมและสถานะตาม Workflow การปิดงาน |
| Related Requirements | FR-CLMRS-06 |

### UC-06 — ส่งต่อและติดตามงาน

| Field | Detail |

| Preconditions | มีรายการงานที่ต้องส่งต่อ |
| Main Success Scenario | 1. เจ้าหน้าที่เปิดรายการ 2. เลือกหน่วยงานปลายทาง 3. ส่งต่องาน 4. ระบบบันทึกการส่งต่อ 5. หน่วยงานรับช่วงรับงาน 6. ระบบแสดงผู้รับผิดชอบปัจจุบัน 7. สามารถติดตามประวัติการส่งต่อได้ |
| Alternate / Exception Flows | A1. ไม่สามารถส่งต่อไปยังหน่วยงานที่เลือก → งานรอการกำหนดผู้รับผิดชอบ |
| Postconditions | มีประวัติการส่งต่อและผู้รับผิดชอบปัจจุบัน |
| Related Requirements | FR-CLMRS-07 |
