## 2. Acceptance Criteria

### AC-01 — การส่งคำขอแจ้งซ่อมสำเร็จ (FR-CLMRS-01)
- **Given** ผู้ใช้งาน (นักศึกษา/อาจารย์ผู้สอน) เข้าสู่ระบบ CLMRS และอยู่ในหน้า "แจ้งซ่อมอุปกรณ์/ห้องเรียน"
- **When** ผู้ใช้งานกรอกข้อมูลในฟิลด์บังคับครบถ้วนแล้วกดปุ่ม "ส่งฟอร์ม"
- **Then** ระบบบันทึกข้อมูลคำขอลงฐานข้อมูล และแสดงหน้าจอยืนยันพร้อมเลขที่อ้างอิง **Ticket ID** ให้ผู้ใช้เห็นภายใน **3 วินาที**

### AC-02 — ความพร้อมใช้งานของช่องทางมาตรฐาน (FR-CLMRS-01)
- **Given** ระบบเชื่อมต่อเครือข่ายปกติ
- **When** ผู้ใช้งานที่ผ่านการรับรองตัวตนเข้าใช้งานพอร์ทัลแจ้งซ่อม
- **Then** ฟอร์มแจ้งซ่อมมาตรฐานต้องเปิดใช้งานได้ตลอด 24 ชั่วโมง และรองรับทั้งอุปกรณ์มือถือและคอมพิวเตอร์ (Responsive Design)

### AC-03 — การตรวจสอบฟิลด์บังคับ (FR-CLMRS-02)
- **Given** ผู้ใช้งานกำลังกรอกฟอร์มแจ้งซ่อม
- **When** ฟอร์มแสดงผล ฟิลด์ **อาคาร**, **ห้อง**, **หมวดหมู่ปัญหา** และ **รายละเอียดปัญหา** ต้องถูกระบุเป็นฟิลด์บังคับ
- **Then** หากผู้ใช้กดส่งโดยเว้นว่างฟิลด์บังคับใด ๆ ระบบต้องไม่อนุญาตให้ส่งฟอร์ม และแสดงข้อความแจ้งฟิลด์ที่ขาดภายใน **1 วินาที**

### AC-04 — การตรวจสอบไฟล์แนบ (FR-CLMRS-02)
- **Given** ผู้ใช้งานต้องการแนบรูปภาพประกอบปัญหา
- **When** สกุลไฟล์เป็น JPEG/PNG และมีขนาดไม่เกิน 5MB
- **Then** ระบบบันทึกไฟล์แนบเข้ากับรายการแจ้งซ่อมและแสดงตัวอย่าง (Preview) ก่อนการยืนยันส่ง

### AC-05 — การจัดลำดับความสำคัญของงาน (FR-CLMRS-03)
- **Given** มีรายการแจ้งซ่อมที่ต้องประเมินความเร่งด่วน
- **When** เจ้าหน้าที่หรือระบบประเมินรายการตามเกณฑ์ความเร่งด่วนที่ได้รับการยืนยัน
- **Then** ระบบต้องแสดงและจัดลำดับงานตาม Priority ที่กำหนด เพื่อให้งานที่มีความเร่งด่วนได้รับการพิจารณาก่อน

### AC-06 — การดึงข้อมูลสถานะงานซ่อมบน Dashboard (FR-CLMRS-04)
- **Given** ผู้แจ้งซ่อมเปิดเข้าหน้า Dashboard "รายการแจ้งซ่อมของฉัน"
- **When** หน้าจอเริ่มโหลดข้อมูล
- **Then** ระบบต้องดึงประวัติและสถานะปัจจุบัน เช่น *รับเรื่องแล้ว*, *กำลังดำเนินการ*, *เสร็จสิ้น*, *ปิดงาน* และแสดงผลเสร็จภายใน **2 วินาที**

### AC-08 — กระบวนการปิดงานและการยืนยัน (FR-CLMRS-06)
- **Given** เจ้าหน้าที่เทคนิคดำเนินการแก้ไขปัญหาเรียบร้อยแล้ว
- **When** เจ้าหน้าที่บันทึกผลการทำงานและส่งคำขอปิดงาน
- **Then** ระบบต้องดำเนินการเปลี่ยนสถานะเป็น "ปิดงาน" ตาม Workflow และ Role ของผู้มีหน้าที่อนุมัติที่ได้รับการยืนยัน

## 4. Use Case Specification

### UC-01 — แจ้งปัญหาอุปกรณ์ / ห้องเรียน
| Field | Detail |
|---|---|
| Primary Actor | นักศึกษา, อาจารย์ผู้สอน |
| Trigger | พบอุปกรณ์หรือห้องเรียน/ห้องปฏิบัติการชำรุด |
| Preconditions | ผู้ใช้งานสามารถเข้าสู่ระบบได้ |
| Main Success Scenario | 1. ผู้ใช้งานเข้าสู่ระบบ<br>2. เลือกเมนูแจ้งปัญหา<br>3. กรอกข้อมูลที่จำเป็น (อาคาร, ห้อง, รายละเอียด)<br>4. กดส่งรายการ<br>5. ระบบตรวจสอบข้อมูลบังคับ<br>6. ระบบบันทึกรายการลงฐานข้อมูล<br>7. ระบบสร้าง Ticket ID อัตโนมัติ<br>8. ระบบแสดงเลขที่อ้างอิงบนหน้าจอ |
| Alternate / Exception Flows | A1. กรอกข้อมูลไม่ครบ ➔ ระบบแสดงข้อความเตือนฟิลด์ที่ขาดและไม่อนุญาตให้ส่ง |
| Postconditions | รายการแจ้งซ่อมถูกบันทึกเรียบร้อยพร้อม Ticket ID |
| Related Requirements | FR-CLMRS-01, FR-CLMRS-02 |

### UC-02 — ติดตามสถานะงานซ่อม
| Field | Detail |
|---|---|
| Primary Actor | นักศึกษา, อาจารย์ผู้สอน |
| Trigger | ต้องการทราบความคืบหน้าของงานซ่อม |
| Preconditions | มีรายการแจ้งซ่อมที่ผู้ใช้งานเป็นผู้แจ้งอยู่ในระบบ |
| Main Success Scenario | 1. ผู้ใช้งานเปิดเข้าหน้า Dashboard<br>2. เลือกดูรายการแจ้งซ่อมของตนเอง<br>3. ระบบตรวจสอบสิทธิ์ผู้ใช้<br>4. ระบบแสดงรายการและสถานะปัจจุบัน (เช่น รับเรื่องแล้ว / กำลังดำเนินการ / ปิดงาน) |
| Alternate / Exception Flows | A1. ไม่พบรายการ ➔ ระบบแสดงข้อความแจ้งว่าไม่มีรายการแจ้งซ่อม |
| Postconditions | ผู้ใช้งานรับทราบสถานะงานซ่อมล่าสุด |
| Related Requirements | FR-CLMRS-04 |

### UC-03 — จัดลำดับงานซ่อม
| Field | Detail |
|---|---|
| Primary Actor | เจ้าหน้าที่เทคนิค |
| Trigger | มีรายการแจ้งซ่อมใหม่เข้ามาในระบบ |
| Preconditions | มีรายการแจ้งซ่อมอยู่ในระบบ |
| Main Success Scenario | 1. เจ้าหน้าที่เปิดดูคิวงาซ่อม<br>2. ระบบประเมินและจัดลำดับงานตามเกณฑ์ความเร่งด่วน<br>3. งานเร่งด่วน (Urgent) ถูกจัดขึ้นอันดับแรกในคิวงานอัตโนมัติ<br>4. เจ้าหน้าที่เลือกรับงานตามลำดับความสำคัญ |
| Alternate / Exception Flows | A1. เกณฑ์ Urgent ยังไม่ชัดเจน ➔ ใช้การกำหนดความเร่งด่วนเบื้องต้นโดยเจ้าหน้าที่ |
| Postconditions | งานได้รับการจัดลำดับคิวเพื่อเริ่มดำเนินการ |
| Related Requirements | FR-CLMRS-03 |

### UC-05 — บันทึกผลและปิดงานซ่อม
| Field | Detail |
|---|---|
| Primary Actor | เจ้าหน้าที่เทคนิค, ผู้รับผิดชอบ / ผู้ยืนยันการปิดงาน |
| Trigger | เจ้าหน้าที่เทคนิคแก้ไขปัญหาเสร็จสิ้น |
| Preconditions | งานซ่อมอยู่ในสถานะกำลังดำเนินการ |
| Main Success Scenario | 1. เจ้าหน้าที่เทคนิคเปิดรายการงาน<br>2. บันทึกผลการซ่อมแซมและรายละเอียดการแก้ไข<br>3. กดส่งขอปิดงาน<br>4. ผู้ยืนยันการปิดงาน (หัวหน้า/ผู้ดูแล) ตรวจสอบผลงาน<br>5. ยืนยันการปิดงานในระบบ<br>6. ระบบเปลี่ยนสถานะงานเป็น "ปิดงาน" (Closed) |
| Alternate / Exception Flows | A1. งานไม่เรียบร้อย ➔ ผู้ยืนยันส่งเรื่องกลับให้เจ้าหน้าที่แก้ไขเพิ่มเติม |
| Postconditions | รายการแจ้งซ่อมถูกปิดอย่างสมบูรณ์พร้อมประวัติการซ่อม |
| Related Requirements | FR-CLMRS-06 |
